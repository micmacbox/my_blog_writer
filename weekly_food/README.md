# 주간 푸드 트렌드 원고 작성기

최근 7일의 공개 검색 자료를 모아 맛집·디저트·음식·재료에 관한 정보성 초안을 만듭니다.
사진 기반 원고 생성기와 코드·의존성·인증·실행 환경을 공유하지 않는 독립 프로젝트입니다. 이 폴더 전체를 별도 저장소로 옮겨 실행할 수 있습니다.

## 앱으로 사용하기

```bash
pip install -r requirements.txt
streamlit run app.py
```

이 프로젝트 폴더 안에서 실행하면 주간 푸드 트렌드 전용 웹앱이 열립니다.
로그인 비밀번호는 환경변수 또는 `.streamlit/secrets.toml`의 `WEEKLY_FOOD_PASSWORD`로 설정합니다.
원고 생성기의 비밀번호나 세션은 공유하지 않습니다.

1. 검색어를 한 줄씩 입력합니다. 지역을 좁히려면 `성수 디저트`, `부산 방송 맛집`처럼 바꿉니다.
2. 기본 기간은 한국 시간으로 오늘을 포함한 7개 날짜입니다. 오늘은 실행 시각까지만 포함합니다.
3. Gemini 또는 Groq와 API 키·모델을 설정하면 구체적인 음식·가게명을 추출하고 문장으로 풀어 씁니다.
4. **1. 이번 주 핫한 주제 찾기**를 눌러 관심도 표·원문 링크·수집 상태를 확인합니다. 이 단계에서는 원고를 만들지 않습니다.
5. **원고로 만들 주제**를 여러 개 선택합니다(최대 10개).
6. 추가 조사 기간(기본 30일), 이미지 방식, 주제별 이미지 수(1~3장)를 지정합니다.
7. 필요하면 **주제별 추가 검색어·이미지 내용 조정**에서 지역/지점과 대표 음식명을 입력합니다.
8. **3. 선택 주제 추가 조사하고 원고·이미지 만들기**를 누릅니다.
9. 원고·이미지 미리보기와 출처를 확인하고 TXT 또는 전체 ZIP을 내려받습니다.

### 선택 주제 추가 조사

선택한 주제마다 이름, 특징·재료, 메뉴·방송 관련 검색어 3개로 수집원을 다시 조회합니다.
추가 조사 기간은 주간 조사 종료 시각을 기준으로 1~90일입니다.
해당 주제명이 제목 또는 요약에 실제로 언급된 자료만 연결합니다.
위키백과에 동일 이름의 문서가 있으면 도입부를 배경 자료로 보강합니다.
배경 자료의 날짜는 **확인일(게시일 아님)**로 표시하고, 기존 주간 관심도 점수에는 반영하지 않습니다.
원고와 별도로 추가 조사 상태·주제별 근거 ID·새로 연결한 자료 수를 저장합니다.
기사 전문이나 영상 자막을 수집하는 기능은 아니므로, 가격·영업시간·방송 출연 내용은 원문을 대조해야 합니다.

### 이미지 가져오기 또는 AI 생성

- **공개 사진 가져오기**: Wikimedia Commons 검색 결과에서 작성자, 출처, 라이선스 URL을 확인한 CC BY·CC BY-SA·CC0·퍼블릭 도메인 이미지만 다운로드합니다. 한국어로 검색 결과가 적으면 이미지 검색어를 영문 음식명으로 바꿔 보세요.
- **AI 이미지 생성**: Gemini API 키와 이미지 생성 모델이 필요합니다. 기본 모델은 `gemini-3.1-flash-image`이고, `GEMINI_IMAGE_MODEL` 또는 화면에서 변경할 수 있습니다. 텍스트용 Gemini 키를 함께 쓸 수 있지만 이미지 모델 사용 권한·요금·할당량은 별도로 확인하세요. Groq 텍스트 작성과 Gemini 이미지 생성을 함께 사용할 수 있습니다.
- 공개 사진은 특정 매장에서 직접 찍은 사진으로 표시하지 않습니다. AI 결과는 실제 매장·제품 사진이 아닌 **설명용 AI 생성 이미지**라고 캡션에 명시합니다. 이미지가 실제 주제와 맞는지는 미리보기에서 확인하세요.
- ZIP에는 `images/`의 실제 JPG 파일, `image_credits.md`의 출처·라이선스, 원고 속 사진 위치·캡션을 포함합니다. AI 이미지에는 모델과 사용한 프롬프트도 기록합니다.
- 공개 사진을 찾지 못하거나 이미지 생성이 실패해도 원고는 유지하고, 누락된 이미지 수와 사유를 표시합니다. 공개 사진 실패 시 유료 AI 생성을 자동으로 실행하지 않습니다.
- 데모는 주제 선택과 원고 생성만 시연하며 추가 검색·이미지 API를 호출하지 않습니다.

이 단계별 선택 기능은 웹앱에서 제공합니다. CLI는 기존처럼 상위 N개를 한 번에 작성하며 이미지 API를 자동 호출하지 않습니다.

키가 없어도 **근거 정리 (AI 없이)**로 공개 뉴스 RSS 수집과 제목 기반 원고 생성을 사용할 수 있습니다.
AI가 없는 결과는 제목에 반복 등장한 음식명을 우선 묶습니다. 등록된 음식 접미어/이름으로 찾지 못하면 비슷한 뉴스 제목을 묶습니다. 개별 가게명의 정확한 추출이 필요한 경우 AI를 설정하거나 **비교할 음식·가게명**에 관심 대상을 직접 적으세요.
AI 없이 나오는 초안은 제목·출처 중심의 조사 메모에 가깝고, 완성형 설명문은 AI 설정 후 생성할 수 있습니다.

**가상 자료로 기능 시연**은 네트워크/API 호출 없이 작동합니다. 데모의 음식·링크는 실제 조사 결과가 아닙니다.

## 수집 범위와 키

| 수집원 | 설정 | 수집하는 정보 |
| --- | --- | --- |
| Google News 공개 RSS | 키 불필요 | 기사 제목, 게시일, 발행 매체, 링크 |
| 네이버 뉴스 검색 API (NAVER API HUB) | `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `NAVER_API_MODE` | 제목, 검색 요약, 게시일, 원문 링크 |
| 네이버 블로그 검색 API | 위와 동일 | 제목, 검색 요약, 작성일, 작성자, 링크 |
| YouTube Data API v3 | `YOUTUBE_API_KEY` | 영상 제목·설명, 게시일, 채널, 수집 시점 누적 조회수 |
| Gemini (선택) | `GEMINI_API_KEY` 또는 `GOOGLE_API_KEY`, `GEMINI_MODEL` | 근거에서 주제 추출, 정보성 문장 작성 |
| Groq (선택) | `GROQ_API_KEY`, `GROQ_MODEL` | 위와 동일. 모델 ID 지정 필요 |

앱에서는 **트렌드 수집 설정** 입력, 환경변수, Streamlit Secrets를 지원합니다.
CLI는 환경변수를 사용합니다. `.env`와 `.streamlit/secrets.toml`을 자동으로 읽지 않습니다.
API 키는 결과 JSON/ZIP에 저장하지 않습니다. 설정 JSON에도 키를 넣지 마세요.
필요한 패키지는 기존 `requirements.txt`에 포함되어 있습니다. AI 없는 CLI에는 `requests`만 필요합니다(Python 3.9 이상).

Streamlit Secrets 예시(비밀번호를 설정하고 사용할 수집원만 추가):

```toml
WEEKLY_FOOD_PASSWORD = "본인만_아는_긴_비밀번호"
NAVER_CLIENT_ID = "발급받은_ID"
NAVER_CLIENT_SECRET = "발급받은_Secret"
NAVER_API_MODE = "hub"
YOUTUBE_API_KEY = "발급받은_키"
GEMINI_API_KEY = "발급받은_키"
GEMINI_MODEL = "gemini-3.1-flash-lite"
# Groq 사용 시 GROQ_API_KEY, GROQ_MODEL도 설정합니다.
```

### 네이버 검색 API 신규 발급 (2026년 11월 기준)

네이버 개발자센터는 **2026년 7월 31일부터 검색 API 신규 신청을 종료**했습니다.
현재는 [네이버 클라우드 콘솔](https://console.ncloud.com/)의 **NAVER API HUB**에서 발급받습니다.

1. 네이버 클라우드에 가입·로그인하고 한국 리전을 선택합니다.
2. **Menu → All Services → Application Services → NAVER API HUB**로 이동합니다.
3. 최초 이용 시 **Subscription → 서비스 이용 신청**에서 서비스 이용 절차를 진행합니다.
4. **Application → Application 등록**에서 **NAVER 검색** 카테고리의 **뉴스**, **블로그**를 선택합니다.
5. Application 이름을 입력합니다. 예: `weekly-food` (영문·숫자·하이픈, 최대 20자).
6. 등록한 Application의 **인증 정보**에서 **Client ID**, **Client Secret**을 복사합니다.
7. 앱에서 **네이버 키 발급처 → NAVER API HUB (신규 발급)**를 선택하고 두 값을 입력합니다.

Secrets의 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` 이름은 그대로 사용합니다.
신규 키는 기본값인 `NAVER_API_MODE="hub"`로 호출합니다.
2026년 7월 31일 이전 개발자센터에서 발급받은 검색 API 키를 사용하는 경우에만
앱에서 **기존 개발자센터 (이전 발급)**를 선택하거나 `NAVER_API_MODE="legacy"`를 설정하세요.
CLI에서는 `--naver-api-mode hub` / `--naver-api-mode legacy`로도 지정할 수 있습니다.
두 발급처는 URL·인증 헤더가 다르므로 키를 서로 바꿔 사용할 수 없습니다.

공식 안내: [신규 신청 종료·이관 공지](https://developers.naver.com/notice/article/32530),
[API HUB Application 등록·인증 정보](https://guide.ncloud-docs.com/docs/apihub-application).

Gemini 기본 모델은 `gemini-3.1-flash-lite`이며 수집 설정·`--model`·환경변수로 변경할 수 있습니다.
계정에서 사용 가능한 모델과 할당량은 제공자 콘솔에서 확인하세요. 검색·AI API의 사용 요금과 할당량은 각 계정에 적용됩니다.

## 터미널로 사용하기

이 README가 있는 Weekly Food 프로젝트 폴더에서 실행합니다.

```bash
# 네트워크 없이 기능 확인
python3 -m weekly_food --demo

# 키 없이 실제 공개 뉴스 수집, 기본 최근 7일, 상위 5개 원고
python3 -m weekly_food --provider none --sources rss

# 기본 검색어·사용 가능한 모든 수집원 사용. 설정된 키로 AI도 자동 선택
python3 -m weekly_food --config weekly_food.example.json

# 지역과 분야를 좁히기
python3 -m weekly_food --query '성수 디저트' --query '서울 방송 맛집' --top 3

# 특정 대상을 비교하기: 실제 검색 결과에 이름이 있는 자료만 연결
python3 -m weekly_food --query '관심가게명' --focus '관심가게명' --min-sources 2

# 특정 종료일을 포함한 7일치 게시 자료
python3 -m weekly_food --end-date 2026-11-01 --days 7

# 전체 옵션
python3 -m weekly_food --help
```

`--provider auto`는 Gemini 키 → Groq 키 → AI 없음 순으로 선택합니다.
Groq만 설정했을 때는 `GROQ_MODEL` 또는 `--model`을 반드시 지정하세요.
AI 요청이나 응답 검증이 실패하면 해당 단계만 제목 기반 묶음/근거 정리로 대체하고 사유를 결과에 기록합니다.

`weekly_food.example.json`을 복사해 `queries`, `focus`, `sources`를 수정할 수 있습니다.
`--query`, `--focus`, `--sources`를 지정하면 해당 설정 파일 값보다 우선합니다.
검색어는 최대 30개, 검색어·수집원별 기본 20개/최대 50개 결과만 조회합니다. 추가 페이지는 조회하지 않습니다.
따라서 검색 결과 전체 또는 모든 SNS 게시물을 조사하는 프로그램은 아닙니다.

## 주간 반복 실행

프로그램은 실행할 때마다 지정 기간을 계산합니다. 아래는 매주 월요일 오전 9시 실행하는 macOS/Linux cron 예시입니다.
이 설정을 자동으로 설치하지는 않습니다.

```cron
0 9 * * 1 cd /경로/weekly_food && /경로/weekly_food/.venv/bin/python -m weekly_food --config weekly_food.example.json >> /tmp/weekly-food.log 2>&1
```

`.venv` 생성과 패키지 설치 후 `crontab -e`에서 설정하세요. 실행 시각은 PC의 시간대 기준입니다.
PC가 켜져 있어야 하며 cron은 터미널의 API 키 환경변수를 자동으로 가져오지 않습니다.
예약 실행 환경에도 키·모델 변수를 별도로 공급해야 합니다. 키가 없으면 공개 RSS와 근거 정리 모드로 동작합니다.
매주 완결된 월~일을 조사하려면 월요일에 전날 날짜를 `--end-date`로 지정하세요.
기본값은 언제 실행하든 오늘을 포함한 최근 7개 날짜입니다.
이 프로그램을 위한 별도 상시 서버는 필요하지 않습니다.

## 저장 결과

CLI는 `output/weekly_food/실행일시_고유문자/` 아래에 매번 새 폴더를 만듭니다.

```text
rankings.md           # 주제별 점수, 수집 성공/오류/제외 상태
sources.json          # 날짜 필터·중복 제거 후 남은 자료와 링크
report.json           # 점수 구성, 주제별 근거 ID, 원고, 수집 상태
drafts/01_주제.md      # 정보성 초안 + 문단별 출처 ID + 원문 링크
drafts/01_주제.txt
images/파일명.jpg      # 이미지 준비가 성공한 경우 실제 사진/AI 이미지
image_credits.md      # 사진별 출처·라이선스 또는 AI 생성 표시
review_checklist.md   # 원문 대조·가격/영업정보 확인 항목
weekly_food.zip       # 위 결과 묶음
```

표본이 부족하면 순위나 원고를 꾸며내지 않습니다. 보고서는 저장하고 CLI 종료 코드 `2`를 반환합니다.
정상 생성은 `0`, 입력/설정 오류는 `1`입니다. 원고 수는 기준을 충족한 주제 수에 따라 요청보다 적을 수 있습니다.

## ‘핫하다’의 의미와 원고 기준

- **기간**: 해당 기간에 *게시된* 자료를 대상으로 합니다. 예전 영상의 이번 주 재유행이나 실제 방송 날짜를 추적하는 기능은 아닙니다.
- **관심도**: 독립 발행자 수 35점, 뉴스/블로그/유튜브 유형 다양성 25점, 최신성 25점, 유튜브 누적 조회수의 일평균 환산 15점입니다. 정확한 공식은 결과에 기록합니다.
- **중복**: 같은 URL과 동일한 제목은 하나로 줄입니다. 같은 매체/블로그/채널의 여러 자료로 발행자 수를 부풀리지 않습니다. 전재·협찬·동일 운영자까지 완전히 식별하지는 못합니다.
- **최소 근거**: 기본 자료 2개 이상, 서로 다른 발행자 2곳 이상인 주제만 순위에 포함합니다. 1로 낮춘 결과는 단일 출처일 수 있습니다.
- **비교 한계**: 전국 실측 인기 순위·검색량·맛 평가가 아닙니다. 유튜브 조회수는 수집 시점의 누적값이며 이번 주 증가량이 아닙니다. 과거 종료일 조사에서는 당시 조회수를 복원할 수 없어 유튜브 반응 점수를 0점으로 둡니다.
- **SNS·TV**: 공개 뉴스/블로그에 언급된 SNS 화제·방송 관련 소식과 공개 유튜브 검색 결과를 수집합니다. 인스타그램·틱톡의 비공개/로그인 게시물이나 방송 자막을 직접 수집하지 않습니다. 방송 출연 사실은 원문/영상으로 확인해야 합니다.
- **AI**: 플랫폼별로 고르게 고른 최신 자료 최대 120건에서 구체적인 이름을 찾습니다. 이름이 실제 제목·요약에 있는 자료만 연결합니다. 나머지 자료는 제목 유사도 묶음 후보로 남깁니다. 각 원고 작성에는 관련 최신 자료 최대 12건을 사용합니다.
- **글**: 직접 다녀온 후기·내돈내산 경험을 만들지 않고, 검색 제목·요약·영상 설명·연결된 배경 자료를 바탕으로 한 초안임을 표시합니다. 기사 전문과 재사용 허락이 확인되지 않은 사진을 복사하지 않습니다.
- **사실 확인**: AI의 문단별 출처와 숫자·일부 미확인 표현을 기계 검사하지만, 문장의 진실성까지 보장하는 검증은 아닙니다. 동명 매장/지점·지역, 가격·영업시간·방송 내용은 원문과 공식 안내로 검토하세요.
- **게시**: 파일 생성만 수행합니다. 네이버 편집기 입력·사진 첨부·임시저장·발행은 수행하지 않습니다.

실패는 수집 상태에 기록됩니다. 네이버 검색/유튜브 API를 함께 설정하면 조사 범위를 넓힐 수 있습니다.

## 실용 포스팅 유형 (2026-11 적용)

주제 선택 후 **주제별 포스팅 유형·기준자료·이미지 설정**에서 각 주제의 유형을 지정합니다.
맛집은 식당 방문 가이드, 음식·디저트·재료는 만들기 유형을 기본으로 제안하며 직접 바꿀 수 있습니다.

- **레시피·베이킹 만들기**: 음식 소개, 분량·준비 시간, 재료·계량, 도구, 단계별 방법, 발효·굽기 온도/시간, 실패 방지 팁, 보관·재가열을 구분합니다.
- **식당 방문 가이드**: 매장·지점, 대표 메뉴·가격, 주소·가는 길, 영업시간·휴무·브레이크타임, 예약·웨이팅, 주차 위치·요금·지원 조건, 방문 전 체크를 구분합니다.

유형에 맞는 검색어로 추가 조사하고, AI는 요약 원문에 실제로 있는 근거 문구와 출처 ID를 함께 반환합니다.
계량·시간·가격의 숫자와 단위를 근거에 대조하고, 서로 다른 운영 안내가 감지되면 해당 항목을 비워 원문 검토 대상으로 남깁니다.
이 검사는 내용의 진실성이나 같은 지점인지까지 보장하지 않으므로 실제 안내와 대조해야 합니다.

### 기준 원문 보강

검색 제목/요약만으로 완성된 레시피나 정확한 매장 안내를 얻지 못할 수 있습니다.
각 주제의 **기준 레시피/매장 안내 출처 URL**과 **원문**을 입력하면 전체 내용을 추가 근거로 사용합니다.
URL만 입력해서 원문 전체를 자동으로 읽는 기능은 제공하지 않습니다.

레시피는 입력한 기준 원문의 분량·계량·공정·온도·시간만 사용하며 다른 레시피의 수치를 섞지 않습니다.
기준 원문이 없으면 계량과 공정을 임의 생성하지 않고 `[확인 필요]`로 남깁니다.
Gemini/Groq 키가 없을 때도 제공 원문을 아래처럼 항목명과 콜론으로 나누면 출처가 있는 항목별 정리가 가능합니다.

```text
소개: ...
분량: ...
재료: ...
도구: ...
과정: ...
굽기: ...
팁: ...
보관: ...
```

식당 원문은 `소개:`, `매장:`, `메뉴:`, `주소:`, `영업시간:`, `예약:`, `주차:`, `팁:`으로 정리할 수 있습니다.
검증되지 않은 항목은 `[확인 필요]` 및 **자료 보완이 필요한 실용 가이드**로 표시합니다.
사진은 재료·과정·굽기 또는 대표 메뉴 같은 관련 구역에 배치합니다.
AI의 과정 그림은 확보한 근거가 있는 단계만 참고하며, 실제 제작 결과나 실제 매장·동선 사진으로 표시하지 않습니다.
